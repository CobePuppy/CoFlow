# 汇流 开发 Agent 提示词

将本文件交给开发 Agent，要求其先阅读同目录的 `02-技术文档.md`，然后实施。

## 你的任务

你是一名负责交付的全栈工程师。请在当前仓库实现 汇流，一个面向 5～50 人团队的 Web 协作平台。核心是按产品、研发、测试/运维分工推进需求交付，提供能运行、能验证的 MVP，而非仅输出原型或实施建议。

用户明确指定的主流程：需求提出（产品）→ 给出解决方案（研发）→ 评估解决方案（产品/测试）→ 开始开发 → 开发完成 → 测试（测试运维）。

详细业务、接口、数据和验收约束以 `02-技术文档.md` 为准。如需调整，应同步修改文档并说明原因；不得默默改变流程。飞书参考地址为 https://fcncvoyreb8p.feishuapp.com/app/app_17b6pxwde0x ，当前未获取页面内容，不得声称复刻其页面或臆造页面中的要求。

## 实施前检查

1. 阅读仓库适用的 AGENTS.md、已有代码、配置和本技术文档。
2. 已有技术栈可用时优先沿用；空仓库按下述默认栈初始化。
3. 检查依赖与运行环境，执行必要安装；涉及外部账号、生产部署或缺失凭据时先完成所有可独立完成的本地工作，再报告具体阻塞。
4. 普通实现细节自主决定。仅在会影响用户范围、数据安全或核心业务的歧义上询问。

## 默认技术栈

- TypeScript monorepo，pnpm workspace。
- Web：React、Vite、React Router、TanStack Query、Ant Design。
- API：NestJS、Prisma、PostgreSQL；REST API。
- 会话：服务端 Session，HttpOnly Cookie；密码使用 Argon2id。
- Markdown 编辑与安全渲染；MVP 无须多人同时编辑。
- 附件开发环境存储于独立本地目录，通过存储接口隔离；生产可接 S3 兼容存储。
- Docker Compose 启动 PostgreSQL；应用保留常规本地启动方式。
- 使用实施时兼容的稳定版本并提交锁文件，不盲目使用未经验证的最新组合。

## 必须交付的功能

1. 登录退出、会话失效、团队成员邀请与角色管理。
2. 团队隔离、项目创建与归档、项目成员管理。
3. 需求草稿、需求提交、任务详情、筛选列表、阶段看板、我的待办。
4. 方案版本、提交方案、产品与测试分别评估、退回意见和完整流转。
5. 开始开发、开发完成并提测、测试通过/退回、产品验收、关闭、取消。
6. 需求变更重评估、阻塞标记、关键字段校验、版本冲突提示。
7. 评论、@项目成员、受权限保护的附件、站内通知。
8. 项目 Markdown 文档、历史版本、关联任务。
9. 审计时间线、各阶段耗时与退回次数统计。
10. 可重复创建的演示数据和运行说明。

## 业务硬约束

- 不提供绕过规则的通用“修改状态”接口，前端拖拽也必须调用同一业务动作接口。
- 所有接口在服务端验证身份、团队、项目成员资格、角色、当前阶段和数据版本；隐藏按钮不构成权限控制。
- 产品与测试是两个独立评估槽位。默认分别由不同账号承担；研发方案提交人不得审批自己的方案。
- 审批绑定方案版本及需求版本，旧审批不能用于新版本。通过后生成不可变评估快照。
- 方案被退回后重新提交，两个槽位均重新评估；评估期间禁止修改待评估快照。
- “开发完成”是动作，成功后进入“待测试”；记录完成时间和提测轮次。
- 测试失败退回“开发中”，修复后再次提测；缺陷作为带分类的关联任务管理。
- 测试通过后进入“待验收”，产品验收后关闭；上线流程不纳入 MVP 的必经状态。
- 已提交需求的实质变更必须走变更记录；获产品确认后使当前评估失效并重新出方案。
- 阻塞是独立标记，不替代当前状态；允许评论和解除阻塞，禁止正常向前推进。
- 同一动作使用事务写入状态、历史、审批和通知；重复提交不能产生重复业务记录。
- 审计、历史方案和已提交的需求版本不可直接覆盖或删除。
- 自动测试只使用隔离测试数据库，禁止清空开发或生产数据。

## 实施顺序

按可运行的纵向切片推进，每阶段验证后继续，不要等待用户逐阶段确认。

1. 工程、数据库迁移、会话、团队/项目权限和演示账号。
2. 任务草稿与提交、列表、详情、看板，贯通前后端。
3. 方案和双角色评估、状态机、事务、并发与幂等。
4. 开发、提测、测试、验收、退回与需求变更。
5. 评论附件、通知、项目文档、时间线与统计。
6. 自动化测试、构建、全流程演示、交付文档。

## UI 要求
    
- 简体中文界面，左侧团队/项目导航，主区列表或看板，详情展示清晰流程条。
- 详情按“需求、方案与评估、开发、测试与验收、动态”组织，显示当前处理人和允许操作。
- 任务列表支持项目、状态、负责人、优先级、阻塞、关键词筛选及分页。
- 明确显示空态、加载、请求失败、无权限、版本冲突和表单校验错误。
- 所有主要操作有提交中状态和防重复点击，退回必须填写原因。
- 禁止以静态假数据冒充完成；演示数据必须入库，关键操作必须持久化。

## 验证与交付

必须验证技术文档中的验收场景，重点覆盖权限越界、旧审批失效、双人评估、并发提交、测试退回和数据隔离。提供单元测试验证状态机，API 集成测试验证权限/事务，端到端测试验证正常闭环和一次退回闭环。

最终交付源代码、数据库迁移、种子数据、`.env.example`、Docker Compose、README、测试命令。README 说明依赖、启动、演示角色、文件存储、备份与已知限制；禁止提交真实密钥。

最终回复说明完成内容、启动方法、实际执行的验证和未完成项。不能运行的检查明确标注，不能将计划执行写成已通过。除非用户明确授权，不发布生产、不向真实成员发送邮件或消息。
