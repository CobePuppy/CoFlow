# V4：AI推进项目与专业协作交付

用户于2026-10-21确认V4方向：AI帮我推进项目、团队协作与交付更专业。保留V1学生/企业分离、V2项目分身和自回归、V3模块化与独立前端的历史定义。

## 首批实现

入口为企业版、学生版的项目概览。规则扫描未完成需求的阻塞、北京时间逾期、验收标准缺失、研发交接缺失与待验收状态。风险列表最多显示8项；AI读取完整的受限需求摘要。当前处理人沿用业务流程，包括已评估成员排除，不把建议视为新增指派。

成员填写目标，主动调用个人配置的DeepSeek生成行动建议。引用必须属于当前项目的未完成需求，证据必须逐字出现在该需求摘要中。输出最多12项，不能将建议视为已执行工作或真实测试结论。

可直达需求详情，通过既有审批、阻塞、研发交接、测试及验收流程推进。成员确认后可保存为项目文档，关联计划中的需求；也可导出Markdown草稿。生成结果在保存前仅保存在当前页面内存，离开页面会丢失。保存内容是成员确认的建议文档，不是不可篡改的模型原始响应证明。

## 一致性与权限

读取和生成遵循项目及团队成员权限；归档项目仅可读取。生成前、返回前和保存前校验项目、成员、需求版本和摘要指纹。保存及审计同事务，按用户/项目/请求标识幂等；相同标识不同内容拒绝。任务变化失效推进依据缓存，另每30秒刷新；失效计划只供历史参考，保存由服务端再次核对。

使用现有个人API配置、请求超时、并发及频次限制。只在点击生成后向DeepSeek传送项目名称/描述、目标和需求摘要，不发送讨论历史、完整正文、附件或文档正文。单项目最多200项未完成需求，超限明确拒绝；摘要总字符遵循既有10万字符限制，不截断后假装完整。规则信号仅代表资料缺口，不等于真实执行结果。

本轮无数据库迁移；复用Document、审计与幂等记录。接口新增GET /projects/:id/assistant、POST /projects/:id/assistant/run及POST /projects/:id/assistant/save。后两者沿用会话、CSRF及Origin保护。

## 后续工作范围

1. 目标与里程碑：关联已有迭代，比较目标、计划与实际结果。
2. 团队协同：行动认领、明确交付物、到期跟进和站内通知。
3. 决策落地：将项目分身的选择结果转入行动计划，保留来源。
4. 交付复盘：以真实交接、测试与验收记录生成偏差分析，用户选择是否调整。

以上为后续方向，本轮不宣称已实现自主执行、自动排程、多Agent研发或自动验收。
