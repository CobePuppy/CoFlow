# 竞赛团队共享与同步修复

## 原因

竞赛记录持久化在项目下，并非个人数据；但原竞赛页面只查询当前项目。项目列表只包含当前用户加入的项目，所以同团队不同成员的默认项目不同，或新成员尚未加入项目时，会看不到其他成员登记的竞赛。此外列表没有跨会话刷新，已打开页面不能自动看到他人的新增或修改。

## 修复规则

- 学生版竞赛管理默认查询GET /api/v1/workspaces/:id/competitions，按团队展示全部竞赛登记，包括所属项目、参赛阶段和备注等登记信息。
- 支持切换团队全部/当前项目视图。每15秒同步并可手动刷新，竞赛页的项目成员列表也周期刷新。
- 团队成员可读团队竞赛登记；尚未加入所属项目时只读，编辑、FirstStep、ProofLoop及项目文书仍要求项目成员权限。未向团队外用户开放任何记录。
- 现有项目级竞赛接口保留，文书中心仍按项目筛选；无数据库迁移，旧竞赛自动出现在团队视图。
- 登记新竞赛使用上方选择的未归档项目；跨项目卡片进入参赛材料时使用记录真实projectId，避免跳到当前选中的其他项目。
- 修改竞赛后同时使竞赛相关查询失效，保持当前列表与文书中心一致；后台更新不会覆盖正在编辑的表单，旧版本提交由服务端返回冲突。

## 验证

数据库集成验证同团队成员共享列表、仅团队成员只读、加入项目后访问标记变化、非团队成员拒绝、项目写权限与版本冲突。浏览器使用两个独立登录会话验证负责人登记后队友通过轮询看到记录、未入项目时只读、加入项目后编辑、负责人刷新看到修改，以及跨项目跳转。

验证结果：2项数据库集成测试通过；双账号共享专项、原学生版竞赛/文书流程、ProofLoop专项共3项浏览器场景分批通过。手动刷新同时刷新当前账号的可访问项目列表，项目成员资格变化无需重新登录。

## 管理员维护入口修复

团队管理员不在项目成员列表时，之前无法编辑竞赛或恢复项目成员资格。本次仅在竞赛登记更新、项目成员列表及增删改接口允许本团队管理员管理；文档、任务及AI材料访问仍要求项目成员资格。竞赛卡片提供“管理参赛成员”入口，可选择团队成员并保存项目角色；未加入项目的管理员仍可编辑竞赛登记。普通团队成员仍只读，归档项目仍禁止修改，跨团队请求仍拒绝。

验证：类型检查、构建、格式检查及2项数据库集成测试通过。双账号浏览器测试通过，覆盖管理员退出项目后编辑竞赛、打开成员管理重新加入自己、恢复项目材料入口，以及普通成员只读和跨账号更新同步。此次没有新增数据库迁移。
