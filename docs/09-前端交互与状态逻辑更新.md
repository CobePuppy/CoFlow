# 前端交互复盘与状态逻辑更新（2026-10-17）

## 复盘结论

此前功能入口已经较完整，但页面状态分散在 URL 和组件内部。用户切换项目、筛选任务、进入详情并返回时，界面和地址可能不一致。本轮先统一状态来源，改善日常使用中的连贯性。

| 发现的问题 | 本轮更新 |
| --- | --- |
| 切换团队/项目时，地址仍写入旧团队或旧项目 | 用单次 URL 更新写入目标标识；切换团队移除旧项目，切换项目清理旧筛选与页码 |
| 刷新后丢失视图、筛选和页码 | 从 URL 读取并校验 view、mode、page、q、status、priority、owner、blocked |
| 进入详情再返回无法回到原位置 | 打开/关闭需求只增删 task 参数，保留项目、视图、筛选和页码，支持浏览器前进后退 |
| 筛选条件清了，控件仍显示旧值 | 搜索框、状态、负责人、优先级和阻塞条件受实际状态控制；增加清空筛选 |
| 待办与项目筛选的阻塞条件语义不一致 | 提取并验证筛选逻辑，明确区分 blocked=true 与 blocked=false |
| 看板超过 100 条只能缩小筛选 | 增加每页最多 100 条的翻页，展示总数和当前页数量，阶段列计数标明按当前页统计 |
| 加载和失败可能被误认成空数据 | 当前任务来源显示对应错误与重试；看板加载显示骨架屏，通知显示独立加载/错误状态 |
| 空结果一律提示创建需求 | 有筛选条件时提示没有符合条件的需求；越界页提供返回第一页入口 |
| 移动端导航缺少完整关闭和滚动行为 | 打开时锁定背景滚动；Escape、切换团队/项目及宽屏恢复时关闭并恢复滚动 |

项目任务列表补充按 id 的稳定次排序，降低更新时间相同导致的翻页顺序不确定性。偏移分页仍不保证并发新增或更新期间的跨页快照一致性。

## 地址示例

`/?app=work&workspace=<团队>&project=<项目>&view=tasks&mode=board&page=2&priority=P1`

复制地址可恢复相同查询条件。任务详情在原地址上增加 task 参数。分页与枚举参数有边界检查，非法值退回默认；权限仍由服务端检查。URL 不属于用户授权来源。

搜索框支持先输入、按 Enter 或搜索按钮提交；清空输入立即移除搜索条件。清空全部筛选后回到第一页，不改变列表或看板模式。切换模式同样回到第一页。

看板展示当前页的阶段分布，翻页继续查看其他需求，并非把所有任务一次渲染到页面。

## 继续可做的前端更新

| 优先级 | 方向 | 建议范围 |
| --- | --- | --- |
| P1 | 常用筛选收藏 | 按用户和项目保存命名筛选，复用本轮 URL 状态模型；缓存损坏和存储禁用应有兜底 |
| P1 | 逾期/阻塞风险入口 | 点击统计卡片进入对应查询；统一时区、截止时间和终态排除规则，并在后端筛选后分页 |
| P1 | 大型列表服务端搜索 | 文档关联选项、文件库逐步改成搜索与分页，保留已选项标题，避免全量载入 |
| P1 | 输入保留与离开提醒 | 文档和需求编辑在离开时提示未保存内容，明确覆盖、取消和冲突恢复行为 |
| P2 | 键盘操作与反馈统一 | 看板卡片可键盘进入；通知的已读动作和导航顺序一致；弹窗关闭恢复焦点 |
| P2 | 组件及响应类型完善 | 减少 Workspace/Portal 的 any，按表单、查询、展示面板拆分 |

上述继续项为候选，本轮没有宣称已实现。
