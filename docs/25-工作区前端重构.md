# 工作区前端重构

依据用户提供的 Makit 截图，围绕工作优先、资料分区、逐步完善和交接预览调整需求工作区。

## 工作入口

我的工作顶部展示待推进、待处理总数、阻塞、逾期。统计仅来自当前团队内分配给当前用户的待办，避免将个人统计误标为团队总量。卡片切换下方分类；任务卡片与风险提醒可直达对应项目的需求详情。逾期按北京时间日历日期计算。保留项目、竞赛日程和知识库入口，不显示没有真实数据支持的迭代进度。

## 创建与详情

快速创建保留标题、所属项目和产品负责人。其他责任分工及背景、正文、验收标准通过“完善更多信息”展开。服务端已有草稿允许部分分工为空的能力；前端发送空字符串兼容现有接口，正式提交仍独立检查人员与评估职责。

详情中的方案、评估、开发交付和测试验收统一归入研发资料，按交付材料分卡展示，最新记录优先；在材料旁放置当前有权执行的操作。保留验收项、AI评审、关联文档及动态附件。

## 流转

流转确认显示当前状态、目标状态、接手人与阶段结果。接手人采用实际需求责任分工，与服务端状态机保持一致；需要改变成员时使用责任转交。双评估的第一次通过仍等待另一评估人，两方通过后交研发。所有操作继续使用既有权限、版本冲突和服务端校验。

没有增加截图中本项目尚未实现的发布阶段、GitHub检查或外部通知，也没有改动服务端状态机。

## 验证

类型检查与前端生产构建通过；需求阶段、提交准备和页面筛选相关单元测试 11 项通过。隔离测试库下验证了正常交付、测试失败后修复再次提测、需求缺项与提交、页面状态与项目切换、创建编辑及手机导航、工作概览分类与研发资料六个浏览器场景。首轮发现重复操作入口，已移除；验收项断言限定到对应页签，移动端检查等待响应布局稳定，相关场景复测通过。截图位于 artifacts/browser/work-overview-desktop.png、work-overview-mobile.png、delivery-materials.png。
