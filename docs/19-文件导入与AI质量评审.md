# 文件导入与AI质量评审

## 文件导入

入口：创建项目、项目设置、创建/编辑需求草稿中的“从文件导入信息”。支持TXT、Markdown、DOCX和文字型PDF，最大8MB及6万字符，PDF最多80页。浏览器本地提取正文，预览可编辑。扫描PDF、图片需先OCR，旧DOC需转换DOCX；表格、多栏、公式和图片内容不保证顺序或完整性，应核对正文。导入操作不自动保存原件为附件，原件仍可使用既有附件功能保存。

“按正文填入说明”无需Key；文件名作为建议标题。“AI整理字段”读取个人设置的DeepSeek模型及已加密保存的Key，用户勾选发送预览正文和计费说明后才调用。只允许提取名称/标题、介绍/描述、背景、目标和验收标准；不会推断成员、状态或权限。确认填入前展示将覆盖的字段，实际保存仍走原业务接口。

正文解析依赖按需加载；PDF worker为本地构建资源，不使用第三方CDN。pdfjs-dist 6.4.299下载包保存在vendor中，与官方锁文件SHA512一致；包路径相对于仓库，支持跨机器安装。因为仅在浏览器解析，pnpm跳过原生canvas可选包。API没有新增解析运行库，发布时前端dist包含完整worker资源。

## AI评审

入口：需求详情“AI评审”页签。选择需求文档、研发方案或测试结果，默认读取当前需求信息、最新已保存研发方案、研发交接和最新测试记录；可选择最多5份本需求关联文档。不会发送评论、成员信息、旧流程历史或全部项目文档。最大10万字符，不自动截断材料。

复用个人设置里的API Key和模型、既有限流与安全上游错误处理，不额外填写Key。每次调用均需确认发送和费用说明，不自动重试。无Key时展示设置链接。本功能检验文档质量，不运行代码或真实测试，不替代人工双人评估及验收，不自动改动审批状态。

输出包括“文档检查通过 / 需要修改 / 材料不足”，至少3项检查，每项提供结论、解释、修改建议及依据。通过项必须有来源引用，引用必须逐字匹配当前发送资料，否则整个结果拒绝保存；检查项和总体结论矛盾也会拒绝。缺少基础需求描述、验收标准或对应方案/测试记录时强制标注材料不足。

评审追加到需求数据aiReviews中，保存评审人、时间、模型、需求版本、关联文档ID和资料摘要，并生成审计事件。写入时重查项目权限、归档状态、需求版本及文档快照，防止长调用期间资料变化。每需求最多50份记录，支持JSON导出。资料变更后旧报告标记需重评；评论和无关历史不使报告过期。没有新增数据库迁移。

## 验证

44项单元测试通过，包含模拟提供商、白名单、引用校验、输出截断、材料不足、配置复用、报告保存及审批状态保留；2项数据库集成测试通过，包含评审权限、同意和版本校验、记录读取与过期检测。

浏览器专项使用真实TXT/DOCX/PDF小样本验证本地解析与需求填入，AI调用通过请求模拟验证个人设置复用、同意校验、报告展示、过期提示及项目字段填入。没有使用用户真实Key进行付费调用。类型检查、生产构建、格式检查通过，构建日志见artifacts/file-ai-build.log。

最终相关浏览器回归6项全部通过：文件解析及AI流程、首页项目成员与文件库、正常多角色交付、缺陷重测交付、需求表单及窄屏导航、四区工作台及项目设置。测试运行器在全部用例输出通过后关闭。本轮尚未部署服务器。
