# 需求模板中心与企业应用规划（2026-10-17）

## 本轮新功能：项目需求模板中心

入口：进入需求协作，在项目页签中选择“需求模板”。新建需求弹窗也可选择模板或将当前草稿保存为模板。

- 管理员、项目产品成员：创建、查看、编辑、启用和停用本项目模板。
- 项目普通成员：查看、套用已启用模板。
- 模板包含标题、背景、目标、需求说明、验收标准和优先级。
- 创建需求时套用模板；已有输入会先确认是否替换。负责人和截止日期保留当前表单值；审批、状态及历史不从模板复制。
- 编辑现有需求草稿时可保存内容为新模板；本轮不支持将模板批量覆盖到已存在的需求。
- 归档项目只读。停用不会删除模板，已创建的需求不受模板后续修改影响。
- 同一项目的模板名称唯一，停用后名称仍保留。重复名称返回冲突，编辑使用 expectedVersion 防止覆盖他人更新。
- 保存模板不会同时创建需求，也不会将尚未保存的表单内容自动提交为需求。

## 存储与接口

新增 RequirementTemplate 表，记录项目、团队、内容 JSON、启用状态、创建人、版本与时间。项目与团队使用复合外键。沿用项目写入锁及归档数据库触发器；创建和修改与审计同事务提交。

| 接口 | 用途 |
| --- | --- |
| GET /api/v1/projects/:id/templates | 返回 items、canManage、readOnly；普通成员仅得到已启用模板 |
| POST /api/v1/projects/:id/templates | 创建模板，参数 name、content、active |
| PATCH /api/v1/templates/:id | 编辑或停用模板，参数 name、content、active、expectedVersion |

content 只接受上述六类内容字段，不能写入负责人、状态、审批或历史。所有写操作沿用会话、CSRF 与 Origin 校验。跨团队访问返回404，无管理权限写入返回403，版本冲突或归档写入返回409。

新增迁移为 202610170001_requirement_templates。本机 coflow 与隔离 coflow_test 已迁移；部署其他环境需先执行 pnpm db:generate 和 pnpm db:migrate，再启动新版本 API。此次本机开发库迁移还补齐此前未应用的 202610160005_qq_bridge；未重置账号或业务数据。

## 下一款应用建议

若面向研发团队，优先“发布与变更管理”：已有需求、测试与验收记录可以直接成为发布依据，新增的是发布批次和执行闭环。

若希望覆盖全公司，优先“工单服务台”：IT、行政和内部服务可共用请求入口，第一版先覆盖提交、分派、处理、确认及知识沉淀，再按实际反馈加入响应期限与升级规则。

会议行动项适合作为较小的一轮独立交付。审批、资产、合同可随后分批建设，先明确业务权限和审计边界。

## 应用扩展基础

新应用应拥有独立业务实体与状态规则。可以逐步抽出应用注册表、应用权限、通用资源引用、附件、通知和审计；任务、工单、审批单、资产不能都塞进当前 Task 的研发状态机。当前通知依赖 taskId，新应用接入前需要设计可兼容的资源引用，不应伪造需求来承载通知。
