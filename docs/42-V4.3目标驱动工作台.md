# V4.3 目标驱动工作台

产品4.3.0，前端3.18.0，后端2.25.0。分类：frontend、backend、feature、maintenance。未部署。

## 本轮反思与落地

上一轮行动、迭代和复盘各自可用，但缺少统一目标，项目概览也随着功能增加变长。本轮新增三项能力：

1. 项目目标：记录负责人、北京时间截止日和达成标准，关联已有迭代及需求；沿用迭代里的里程碑，沿来源需求汇总行动。直接关联和迭代关联去重，取消及回收站单列，需求验收比例不等于目标自动达成。
2. 推进工作台：按全部、指定目标、未关联活跃目标筛选，统一查看待我处理、我的行动、待我确认、阻塞、逾期、等待他人和待认领。每队列最多展示20条并说明总量；可进入原需求、行动跟进及迭代页面。
3. AI规划上下文与批量交接：生成时读取目标、迭代、里程碑、需求关联、已有行动和成果；上下文变化后拒绝旧建议转入或保存。支持一次将最多12项不同需求的建议转为行动，任一失败整批回滚，重试防重。

## 使用与权限

企业版和学生版项目概览统一分为推进工作台、AI推进、行动与复盘、交付统计。切换后保留已经打开的标签页内容。先保存AI计划草稿，再批量转行动；转入本身也会改变规划依据，需要重新生成下一轮建议。

产品成员和团队管理员创建目标，目标负责人也可维护自己目标。所有写操作验证当前团队及项目成员、项目可写状态、目标版本，并同事务写入审计。关联变更需填写原因。目标只归档，不永久删除；归档保留历史和关联，暂停关联调整，仍可维护目标内容和负责人，方便负责人离开后的接续。恢复后重新纳入活跃覆盖范围。

冲突保留输入，可查看最新目标标题、说明、标准、版本，确认后按新版本再次提交。历史仅追加，不覆盖已有事件。目标关联需求不能跨项目移动或永久删除；可先解除关联，或保留回收站记录。有目标历史的项目保留归档。

## 数据与边界

新增迁移20261022020000_project_goals，增加ProjectGoal、ProjectGoalTask和ProjectGoalIteration。数据库约束保护项目范围、目标事件追加、关联范围及负责人资格。迁移仅在隔离coflow_test应用；生产尚未迁移。正式部署前需要备份并按既有迁移流程执行，不能将构建成功视为发布。

工作台最多500项需求（含终止及回收站）、100项目标、200个迭代、500项行动；AI沿用最多200项活跃需求，并额外限制1000个里程碑、500项迭代需求，超限明确拒绝。目标最多直接关联200项需求、20个迭代，历史最多1000条。

AI上下文会向用户配置的DeepSeek发送选定项目规划与行动成果摘要；不包含事件历史。原文证据仍必须来自对应需求资料，不能凭规划内容编造证据。真实模型效果尚未验证，自动执行外部操作、跨项目调度和目标达成认证不在本轮范围。
