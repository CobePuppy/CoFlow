# 四轮 Plan → Action 升级记录

日期：2026-10-21（Asia/Shanghai）。起点为 product/web 3.8.0、api 2.16.0。

## 第一轮：讨论与决策（3.9.0）

Plan：把普通评论扩展为可追踪的澄清过程，帮助成员找到未解决问题及讨论结论。

Action：增加问题、决策、回复、待解决及决策筛选、内容与作者搜索。记录当时的需求版本；问题作者或需求负责人填写原因后解决或重开问题。问题状态追加到评论事件，不修改既有历史，也不直接修改正式需求或审批。

验证：91 项单元、8 项隔离 PostgreSQL 集成、2 项双版本浏览器场景、类型、格式及生产构建通过。追加状态事件后，既有不可改写历史保护回归通过。

版本：product/web 3.9.0，api 2.17.0；frontend、backend、feature，validated，未部署。

## 第二轮：文件查找（3.10.0）

Plan：个人及团队文件不断增多时，仍能快速找到开发规范、手册等资料。

Action：新增类型、团队仅看本人上传、时间/名称/大小排序，与搜索组合后服务端分页；查找条件保存在网址，刷新及版本切换保留上下文，一键清除及空结果提示帮助恢复。上传完成回到最新文件。原项目资料与访问权限保留。

验证：93 项单元、9 项隔离集成、4 项双版本新旧文件空间浏览器场景、类型、格式及生产构建通过；24 文件跨页顺序与数据库预期一致，两版手机截图复核。

版本：product/web 3.10.0，api 2.18.0；frontend、backend、feature，validated，未部署。

取舍：文件内容换版仍需单独设计历史下载、备份、清理及引用语义；本轮先解决查找能力，不改变原文件字节的不可变约束。

## 第三轮：讨论输入保护（3.11.0）

Plan：讨论或回复写到一半时，刷新、关闭详情、遇到并发冲突均可继续处理。

Action：复用浏览器工作副本，保存正文、类型和回复对象；按账号、团队、项目、需求隔离，提及成员恢复后重新选择。成功发表清除本页副本，失败保留。详情关闭和返回有未保存提示；正式需求换版要求核对，旧版本副本只供查看复制。加载按钮增加稳定的可访问名称。

验证：93 项单元、9 项不同浏览器场景经分批复验通过，包括原需求、正文、方案工作副本，类型、格式及双版本前端生产构建通过，两版手机截图复核。

版本：product/web 3.11.0，api 保持 2.18.0；frontend、feature，validated，未部署。

限制：工作副本只保存在当前浏览器，清理站点数据将移除；问题解决原因仍需提交或复制保留，没有新增跨设备草稿同步。

## 第四轮：关联资料批量读取（3.11.1）

Plan：减少资料列表逐条查询和无关正文传输，保留已有权限与展示行为。

Action：按三类来源批量查询、一次判定管理员维护权限、批量检查附件所属需求删除状态；只读取展示字段，在同一可重复读事务中组装结果。写入及下载继续实时校验，不用缓存绕过授权。

验证：隔离 PostgreSQL 实测 85 条引用的摘要解析执行 6 条 SELECT，输出与 HTTP 接口一致；不含统一会话/项目鉴权、事务控制等前置查询，因此不代表整个 HTTP 请求只执行 6 条 SQL。已检查投影不读取文档正文、修订内容、需求历史或存储键。最终 93 项单元、9 项隔离集成、3 项资料引用浏览器回归、类型、格式及前后端生产构建通过；两版 product3.11.1/web3.11.0/api2.18.1 及功能产物核对通过。维护权限及附件所属需求删除后的失效/下载拒绝补测通过。

版本：product 3.11.1，web 保持 3.11.0，api 2.18.1；backend，validated，未部署。

## 后续独立升级项

- 文件内容历史版本及可下载快照，需要配套备份和引用更新语义。
- 讨论按处理人分配与跨需求待澄清汇总，需明确责任转交规则。
- 前端大资源包仍有构建提示，后续可按实际页面加载数据评估拆包。

本次四轮均无新增数据库迁移；此前 3.5、3.7、3.8 的迁移仍是从旧线上版本升级的必要步骤。最终版本及部署状态以根目录 version.json 和 CHANGELOG.md 为准。
