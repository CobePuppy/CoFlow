# ProofLoop 成果验证闭环

入口：学生版 → 竞赛管理 → 对应竞赛的 ProofLoop 成果验证。

## 基础版

主张可关联评分要求、文书版本、连续原文引用及验证条件。保存时校验同项目权限、版本和原文；源文书变化后显示证据过期，关联并不代表真实性已获认证。

跨文书检查使用个人设置的DeepSeek配置。用户逐次确认发送所选2—6份文书和主张；文书合计最多60000字，总输入最多100000字符。模型返回的每个疑点必须包含来自至少两份不同文书的逐字引用，否则整批拒绝保存。检查结果是待人工核对的疑点，不提供获奖概率或虚构的综合评分。报告仅覆盖所选文书；新检查替换当前报告，已经创建的任务保留在项目中。

主张、证据或所检查文书改变后，旧报告标为过期。过期疑点不能新转任务。补证任务由用户指定5个交付角色，沿用现有项目流程和权限；同一条目重复创建返回原任务。任务完成不会自动证明主张成立。

数据库：202610170004_proofloop。GET /competitions/:id/proof；POST /competitions/:id/proof/claims、check、task。所有路径前缀为 /api/v1。

基础验证：33项单元测试、2项数据库集成通过；浏览器专项已通过。模型调用使用注入或模拟，无真实付费调用。

## 三轮迭代记录

按用户要求，在基础版完成后执行三次“检查—创新思考—编码更新—检查”，每轮在下方补充实际结果。

### 第1轮：补证优先建议（完成）
检查发现缺口列表缺少行动顺序。新增团队重要度1—5、预计工时0.5—80小时，以及时间预算内最多3项建议。采用公开的启发式排序，明确不是竞赛评分或最优排期。字段保存在主张中，兼容旧数据默认值。34项单元测试、2项集成、类型检查及ProofLoop浏览器专项通过。

### 第2轮：署名人工核对与失效机制（完成）
复盘发现任务状态不能代表证据支持结论。新增人工支持/不支持核对、至少20字依据、当前登录用户署名、最近20条历史。核对绑定主张/验证口径/证据的内容摘要；主张或引用变更后失效，文书换版后显示过期；工时调整不改变证据判断。任务状态单独展示，不自动认证主张。35项单元测试、2项集成、类型检查及浏览器专项通过。

### 第3轮：提交与交接证据包（完成）
发现证据关联仍局限于平台内部，导师和接手成员难以整体复查。新增一致性数据库快照导出，JSON包含关联文书正文、版本、正文哈希、主张状态、最近核对历史、AI疑点、任务状态及待处理清单；Markdown作为人读摘要，使用同一快照摘要。快照只在当前界面内存及用户下载文件中保留，不自动提交或对外发布。

生成证据包后可分别下载JSON和Markdown。用 pnpm exec tsx scripts/verify-proof.ts <证据包.json路径> 校验完整性。SHA-256按payload规范化JSON（对象键递归排序，数组保留顺序）计算，文书哈希按UTF-8正文计算。摘要不包含摘要字段或Markdown本身，不提供签名或可信时间戳，也不能证明数据和结论真实。校验脚本返回0表示完整性一致，非0表示失败。

第3轮检查完成：证据包导出、下载、原文摘要、权限与归档读取测试通过；浏览器完整回归11项通过、QQ未配置跳过。截图复查发现窄屏溢出后修正专属网格、长标题和引用布局，并补跑成果验证及学生版2项通过，新增390px下页面无横向溢出断言。补充模型输入白名单，仅发送主张表述/验证条件和所选文书的ID、标题、版本、正文，不发送人工核对历史与任务ID。所有三轮均完成检查、创新判断、编码及复查。

当前边界：证据来源为项目文书，附件正文需先整理为文书；不自动执行实验、不生成真实结果或正式PPT、不预测获奖。补证任务创建为普通需求草稿，任务完成不会自动更改证据判断。模型网络调用使用模拟或注入测试，未执行真实用户Key的付费调用。

最终验证：38项单元测试、2项数据库集成测试通过；完整浏览器执行11项通过、QQ因未配置跳过，窄屏修正后补跑2项通过；类型检查、格式检查、生产构建和证据包校验CLI实测通过。本地开发服务保持可用。
