# CoFlow 3.0 开发指南

安装和运行环境沿用根 README。执行 `pnpm install` 后 postinstall 会构建 contracts；使用忽略脚本安装时须显式执行 `pnpm --filter @coflow/contracts build`。

```powershell
pnpm dev
pnpm typecheck
pnpm test
pnpm test:architecture
pnpm build
```

`pnpm dev` 同时启动 contracts 监听、API 和兼容开发宿主。浏览器使用 `http://localhost:5173/enterprise/` 或 `/student/`；统一 `/` 可选择版本。两版的 app.config.ts 定义各自导航和能力。共享页面放 web-core/features，学生专属业务放 student-web/features，通用展示放 ui，纯业务约定放 contracts。

`pnpm build` 按 contracts → API → 两个前端的顺序构建，最终由 apps/web/dist 聚合交付。分别执行 `pnpm --filter @coflow/enterprise-web build`、`pnpm --filter @coflow/student-web build` 可检查单版构建；单版产物不会自动替换聚合发布目录。

数据库集成和浏览器测试仅允许 `.env` 中与开发库不同的 `TEST_DATABASE_URL`，数据库名必须为 coflow_test。先执行 `pnpm test:prepare`；不要将开发库或生产库设置为测试库。API 集成与浏览器回归应顺序运行，避免共享测试记录和故障注入相互影响。完整浏览器场景大量注册可能触发正常的注册限流，可分批启动独立测试服务复验，不修改生产限流策略。

旧 scripts 根路径保留兼容包装，实际实现位于对应分类目录。不要把 artifacts、storage、backups、.local-pg 或 .env 当作源码搬迁；这些目录与实际运行数据的路径保持原样。
