# FirstStepAgent 竞赛启动机制（2026-10-17）

## 用途与入口

学生版 → 竞赛管理 → 对应竞赛卡片的“FirstStepAgent 分析竞赛”。它将用户提供的赛题转换为可执行的启动材料，不自动完成竞赛、执行代码、访问通知链接或提交材料。

本仓库此前没有同名组件，本轮 FirstStepAgent 是 CoFlow 自有的竞赛启动工作流：资料检查、需求分析、方案规划、结构化生成、校验与人工核对。首版使用一次结构化模型调用生成整套材料，再以程序检查输出格式和完整性；不是多个后台代理自动相互调用。

## 用户操作引导

1. 在官方通知中核对赛题，粘贴赛题正文、评分及交付要求，至少40字，最多30000字。只有竞赛名称和网址时不要直接推断规则。
2. 填写团队人数、技能、可用时间，以及预算、平台、数据和现有成果。设置PPT页数与答辩时长。
3. 先用“预览提示词（无需Key）”检查完整系统提示词和将发送的资料；可以复制到其他工具手动使用。
4. 前往 [DeepSeek官方平台](https://platform.deepseek.com/) 登录，在平台中创建自己的API Key并检查额度；在CoFlow个人设置 → AI服务中保存Key，所有竞赛共用。不要把Key发到聊天或写进赛题正文。
5. 默认选择DeepSeek Flash；也可选V4 Pro。可在个人设置点击“验证已保存配置”，该操作只查询模型列表，不发送赛题。
6. 阅读并勾选资料发送和计费确认，点击“使用我的Key生成6份成果”。生成不自动重试，最长等待约2分钟。
7. 先核对待确认问题和官方规则，再复制或下载成果。需要团队协作时，点击“保存6份草稿到文书中心”。

Key无效、无权限、余额不足、限流、网络超时或输出不完整时，会给出可读提示；DeepSeek认证失败不会将用户踢出CoFlow。生成失败时保留输入和已有成果，生成成功或失败均保留账号中的配置，不需要重新填写Key。

## 六份成果

| 成果 | 预期内容 |
| --- | --- |
| 竞赛分析与需求拆解 | 目标、题目依据、交付物、范围、风险及缺失信息 |
| 开发执行提示词 | 可复制给开发助手的背景、分阶段任务、边界、输入输出与验收要求 |
| 技术栈与架构文档 | 推荐与备选方案、选型依据、模块/数据流、环境与配置、验证部署路线 |
| PPT生成提示词 | 受众、页数、时长、逐页标题、要点、证据、图示、演讲备注、视觉与引用要求 |
| 里程碑与分工计划 | 阶段、角色、依赖、交付物与退出标准 |
| 验证与提交检查清单 | 可复现、格式、引用、授权、隐私、提交与答辩检查 |

另列“优先确认的问题”。所有成果标记为AI草稿，不能替代官方要求、实际实验或人工判断。首版输出PPT生成提示词与Markdown，不生成PPTX文件。对非软件类竞赛，提示词要求按实际题型选择工具，不默认强加Web后端或算法模型。

## Key、资料与费用

- 首版仅接DeepSeek官方固定HTTPS地址，默认模型`deepseek-flash`，可选`deepseek-v4-pro`。不接受用户填写任意服务地址，也不读取管理员Key代替用户调用。
- Key按账号使用AES-256-GCM加密存入UserSettings，随机nonce且绑定用户ID。完整Key不返回前端，不写入浏览器存储、项目文档或应用日志。支持替换和删除。
- 调用经CoFlow后端转发，服务端仅在调用时解密Key。应用错误日志仅记录请求标识、错误代码和状态，不记录请求正文或上游错误原文。生产环境应沿用HTTPS部署要求。
- 发送给DeepSeek的内容为用户输入的赛题、团队、限制、PPT参数，以及当前竞赛的名称、主办方、截止日期、备注和通知网址。不会自动发送项目全部任务、知识库或附件。
- 模型请求可能计费，以[官方计费页面](https://api-docs.deepseek.com/quick_start/pricing/)和账号额度为准，本页面不固定展示价格。
- 无Key的预览仅在本应用内组装提示词，不调用模型。真实生成必须先在个人设置保存Key，并逐次确认发送资料与费用。测试桩不作为真实生成结果展示给生产用户。

模型与接口参数核对来源：[官方首次调用文档](https://api-docs.deepseek.com/)、[JSON输出说明](https://api-docs.deepseek.com/guides/json_mode/)。官方可能调整模型名称，后续需跟随文档维护；模型可用性可通过面板验证。

## 服务端机制

新增接口：

- POST `/api/v1/competitions/:id/firststep/preview`：校验赛题输入并返回实际提示词，不需要Key。
- POST `/api/v1/settings/ai/verify`：使用当前账号已保存的Key查询官方模型列表。
- POST `/api/v1/competitions/:id/firststep/run`：从个人设置读取Key，要求模型、brief、expectedVersion和consent=true（不接受请求中的apiKey），生成后返回六节成果、待确认问题及Token用量。
- POST `/api/v1/competitions/:id/firststep/save`：要求bundle、expectedVersion和requestKey，一次保存六份项目文档。

全部接口沿用会话、CSRF/Origin及项目权限校验。归档项目可预览但不能生成或保存；个人设置独立于项目。真实生成前后都会检查项目访问和竞赛版本；保存再次检查归档、权限与版本。

模型返回使用JSON模式，要求六个内容字段及questions，检查结束原因、章节长度、总响应大小与结构。拒绝空、截断、损坏和缺章输出；不把不完整结果静默保存。模型输入和输出中的当前Key做防回显处理，但这不替代用户检查资料中其他敏感信息。

同一用户同时最多一个Key验证或生成请求，单进程内每10分钟最多6次，不自动重发付费请求。正式多实例部署应将限制迁移到共享存储。当前不是分布式配额系统。

生成成功记录FIRSTSTEP_GENERATE审计，不持久化生成输入或输出，Key独立存储在个人设置。点击保存后，六份文档与审计同事务落库；requestKey与内容摘要用于幂等重试，重复保存不会重复创建文档。保存的内容都带“尚未人工核对”标记。未保存的成果保留在当前面板，刷新后消失；可先下载Markdown。

新增UserSettings及迁移202610170003_user_settings；生成成果仍复用Document、AuditEvent和IdempotencyRecord。

## 验证与边界

- 31项单元测试通过，包含固定调用地址、Key不进入提示词、上游失败脱敏、JSON完整性校验、模型验证和单用户并发限制。
- 2项数据库集成测试通过，包含无Key预览、未同意时拒绝生成、权限/归档校验及六文档幂等保存。
- 浏览器FirstStep专项使用模拟模型，验证引导、失败恢复、个人配置刷新保持、请求不携带Key、下载和保存，未使用真实Key或实际付费调用。
