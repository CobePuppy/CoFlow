# CoFlow 3.0 升级与回滚

本轮为源码与交付结构升级，不代表已经部署。部署前先备份数据库、附件和稳定的 SETTINGS_ENCRYPTION_KEY；沿用现有 Windows 更新器的备份、校验及回滚流程。

## 产物

- API 仍为 apps/api/dist/main.js，contracts 已内联，运行时第三方依赖沿用 Node 安装环境。
- 前端仍以 apps/web/dist 为发布根，内部新增 enterprise/ 和 student/ 两套独立资源。必须整体交付两套目录及根公共资源，不能只复制一个 index.html。
- 发布包包含 version.json、CHANGELOG.md、历史迁移及生成的 Prisma 客户端；更新器白名单允许更新这两个版本记录文件。
- 启动脚本检查两个版本的 index.html。API 根据路径提供对应 SPA 页面，旧根路径深链接仍可使用。

## 检查与升级

```powershell
pnpm build
pnpm release:package
node artifacts/CoFlow-v3.0.0/platform-update.mjs --root <安装目录> --verify-only
```

输出目录必须尚不存在；需要重打包时使用新的目录参数。verify-only 只检查文件校验和、白名单、历史迁移一致性及加密密钥格式，不执行数据库迁移或部署。实际安装使用包内现有更新入口，先停止服务并确保备份可用。

3.0 结构重构本身没有新增数据库模型或迁移。若安装环境仍为 2.10.0，包中包含此前 2.11/2.12 GitHub 功能迁移，实际升级仍须按更新器流程应用；不能因 3.0 没有新迁移而跳过已有待应用迁移。GitHub 私有仓库仍须单独配置 GitHub App，不因结构升级自动获得授权。

服务依照源码或编译入口向上查找包含 version.json 与 prisma 的根目录；特殊布局可设置 COFLOW_ROOT 为绝对安装根路径。相对 STORAGE_DIR 仍相对于该根目录。不要重新生成或替换现有加密密钥。

部署后验证 `/api/v1/health`、两个版本入口、登录、需求深链接、静态资源和设置切换；再核对 release.json 与 version.json 中的产品版本。只有真实部署并通过运行检查才可把状态改为 released。回滚沿用更新器生成的原文件备份；有数据库迁移时同时遵守数据库恢复说明，不只替换前端。
