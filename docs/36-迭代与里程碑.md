# 迭代与里程碑

产品/前端3.8.0，后端2.16.0。企业版与学生版共用计划规则。

## 工作方式

从项目导航进入“迭代与里程碑”，创建阶段目标、负责人及起止日期。里程碑是迭代内的交付检查点，截止日期必须在迭代范围内。可搜索需求标题或CF编号，分页选择，单次加入最多50项；一个迭代最多2000项需求、50个里程碑。同一需求只安排在一个迭代，跨迭代调整前须先从原迭代移出。

加入、移出和更新安排只影响计划，不改动需求正文、任务数据版本及交付流程。需求详情提供迭代安排和返回计划入口；项目切换隔离数据，刷新保留所选迭代、计划分页及筛选，版本切换保留迭代上下文。

## 进度与延期

按当前有效需求条数计算：只有CLOSED（已验收）计入完成；CANCELLED和回收站需求分别列示，不计入进度分母；空迭代为0%，不标记完成。这是条数进度，不是工时或历史进度快照。里程碑与迭代统计随需求真实状态变化。

计划截止采用需求原截止、所属里程碑截止和迭代结束日期中的最早日期。北京时间截止日当天不算延期；超过该日仍未验收才算延期。支持仅看未验收或延期项，并显示当前处理人、阻塞原因、延期说明。更新安排可切换里程碑或补充真实原因；尚未填写时明确标注，不自动编造原因。

调整迭代起止日期须说明原因，新范围必须覆盖现有里程碑。计划调整记录保存操作者、日期前后变化、需求安排和延期说明，页面显示最近20条；原记录保存在数据库中。

## 权限与并发

团队和项目成员权限共同约束访问。产品成员及有项目访问权限的团队管理员可创建迭代；迭代负责人、产品成员及团队管理员可维护当前计划；其他项目成员只读。负责人须是当前项目成员，项目归档后整个计划只读。已移出项目或团队的成员不能继续读取或维护。

计划独立递增版本，使用项目锁和条件更新处理并发；失败保留输入，核对最新计划后可重试。批量加入全部成功或全部回滚。已有迭代安排的需求禁止直接换项目，数据库也校验需求、迭代与里程碑归属。移出迭代不删除需求、原资料或审批历史。

## 迁移与范围

部署须生成Prisma客户端并执行20261021020000_iterations迁移。新增Iteration、IterationMilestone、IterationTask和IterationEvent表，Task原有正文与流程数据不迁移。数据库备份沿用全库pg_dump，新计划数据随数据库备份保存；无新增文件存储。

本轮提供创建、调整、里程碑、需求安排、验收统计与延期追踪；依赖网络、工时预测、燃尽图及迭代生命周期关闭留待后续。计划不是CoFlow产品发布版本，不将需求完成比例当作实际部署完成。
