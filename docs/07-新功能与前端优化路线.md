# 新功能与前端优化路线（2026-10-17）

## 本轮交付

- 本地数据库恢复；增加 `pnpm db:local:status`、`pnpm db:local:start`，仅检查或启动已有 `.local-pg`，不初始化、不清空。
- 需求工作台、首页、文档和成员管理按需加载。抽出共享请求及查询客户端，保持同一个登录态和缓存实例。
- 页面模块提供中文加载提示和失败后的重新加载入口。
- 文件库增加来源标识及“全部文件 / 需求附件 / 独立文件”筛选，支持忽略大小写的文件名搜索和失败重试。
- 文档关联任务使用分页加载的轻量列表，不再局限前 100 条；支持按标题搜索和加载失败重试。
- 附件与任务选项接口继续检查项目成员身份，跨团队返回 404。

## 事实修订

原复盘将“只加载前 100 条任务”与附件遗漏关联，范围不准确。文件库原本就使用 `GET /projects/:id/attachments` 返回项目全部附件；原先的截断影响文档关联任务选择。本轮保留统一附件接口，并新增超过 100 条任务的浏览器回归，覆盖旧任务附件展示、下载、筛选和文档关联。

## 技术边界

本轮任务选项接口在数据库分页，每页返回 id/title；客户端打开文档编辑器后读取全部分页。它修复完整性，但不是最终的大数据方案：数据库仍读取该页 Task JSON，选项总量仍随任务数量增长。后续应改成服务端按标题搜索及选中项补取。文件列表仍一次获取全部元数据，再由表格分页；文件数很大时同样需要服务端分页。

主 JS 文件由上一轮约 1,312.36 KB（gzip 413.53 KB）降至约 837.19 KB（gzip 269.92 KB）；需求工作台约 68.89 KB，首页约 20.82 KB，文档约 3.62 KB，管理约 3.19 KB。另有公共 UI 块；上述数字不是首屏总下载量，也不是加载耗时结论。主包超过 500 KB 的构建警告仍存在。

## 数据库启动说明

项目实例使用 `127.0.0.1:55432`。之前的 `restricted token / 87` 发生于受限执行环境；获准的普通主机执行环境中，原有 pg_ctl 启动命令成功，健康检查正常，无需删除 PID 文件、重建集群或更改数据库权限。

Windows 示例：先配置 PostgreSQL 工具目录 `PG_BIN`，运行 `pnpm db:local:status`；未启动时运行 `pnpm db:local:start`。若执行环境限制进程检查，状态脚本可能无法确认集群身份，需要在允许读取本地进程状态的终端运行。脚本只面向本项目已有的 55432 实例，Docker 和其他数据库继续按各自部署方式管理。
