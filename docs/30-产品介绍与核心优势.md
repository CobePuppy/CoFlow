# 汇流 CoFlow｜让团队协作从想法走向可验证的成果

> 面向企业研发团队与学生创新团队，连接需求、方案、交付、知识与决策的协作平台。

汇流（CoFlow）将项目推进过程中的需求、分工、文档、测试和验收集中到同一个工作空间，帮助团队明确责任、掌握进度、沉淀成果，并在存在多种方案时，通过有记录的探索与比较做出决策。

## 产品介绍

### 企业版：贯通需求到验收的交付流程

面向产品、研发、测试及运维团队，提供完整的协作链路：

**提交需求 → 研发方案 → 产品与测试分别评估 → 开发交付 → 测试验证 → 产品验收**

通过阶段看板、责任分工、缺陷关联、阻塞记录和操作历史，让每项需求都有清晰的负责人、推进条件和交付依据。

### 学生版：连接竞赛准备、项目执行与成果整理

面向课程项目组、学生创新团队和竞赛队伍，整合项目协作、竞赛管理、文书中心与知识库。

团队可以登记竞赛信息，准备计划书、结题报告和答辩提纲，并借助 AI 启动助手梳理竞赛分析、技术栈、分工计划与提交清单，将准备工作衔接到后续执行。

## 功能全景

### 1. 个人工作台：集中掌握项目、待办与截止时间

登录后可以从工作台查看“我的项目”“我的待办”“竞赛与截止提醒”“最近成果”。企业版聚焦工作截止提醒，学生版结合竞赛安排展示信息。

- 汇集当前团队内本人可访问的项目，快速进入对应工作空间。
- 按截止时间查看待办，直接打开需要处理的需求。
- 从最近成果进入项目文档，减少在不同页面间反复寻找材料。
- 通过应用目录搜索、分类和收藏常用入口，支持窄屏导航。

适合成员每天确认工作重点，也便于在多个项目之间切换。

### 2. 团队与项目管理：让组织关系和项目分工各归其位

一个账号可以创建或加入多个团队，并在不同团队中拥有不同身份。团队管理负责成员与邀请，项目管理负责具体参与者和交付角色。

- 通过团队码加入团队，或使用邀请链接邀请伙伴。
- 查看团队成员、管理团队身份，并切换当前团队。
- 创建、搜索项目，维护项目名称、介绍和项目成员。
- 在项目内分配产品、研发、测试、运维等角色，支持责任转交。
- 归档项目后保留记录并限制写入，需要继续工作时可以恢复。
- 对符合条件的空项目，通过名称确认后删除。

加入团队不会自动获得其全部项目的访问权限，团队身份和项目角色分别管理。

### 3. 需求管理：从想法草稿到正式协作

团队可以逐步完善需求背景、目标、描述和验收标准，明确参与人员后再提交进入交付流程。

- 创建、编辑需求草稿，提交后保留对应的需求版本。
- 通过列表、阶段看板、搜索和筛选定位需求，查看阶段分布。
- 在详情中集中查看正文、负责人、截止时间、关联资料与操作记录。
- 创建需求时选择有权限的项目；符合条件的未提交草稿可以调整所属项目。
- 通过需求模板复用常见内容结构，减少重复录入。
- 在规则允许时取消需求，或删除从未提交的草稿及已取消需求；进行中需求须先取消，存在关联引用时会拦截删除。

这让零散想法逐步成为责任明确、标准清晰的团队工作项。

### 4. 交付流程：把方案、开发、测试和验收连接起来

平台按照明确的阶段推进需求，并根据角色与当前状态提供可执行操作。

| 环节 | 主要操作 | 团队获得的结果 |
| --- | --- | --- |
| 需求提交 | 完善需求、分配责任人、明确验收条件 | 形成共同理解的工作目标 |
| 研发方案 | 编写方案草稿、提交方案版本 | 将需求转为实施思路 |
| 独立评估 | 产品与测试分别评估，必要时退回修改 | 在开发前发现理解和验证缺口 |
| 开发交付 | 记录开发交接与交付信息，提交测试 | 保留研发交付依据 |
| 测试验证 | 记录测试轮次与结果，关联失败缺陷 | 让问题能够追踪和复测 |
| 产品验收 | 按验收项核对并关闭需求 | 形成完整的交付记录 |

需求变更会使原有审批失效，需要重新确认；阻断缺陷未关闭时不能直接放行，减少资料与实际流程脱节。

### 5. 日常沟通与过程追踪：保留问题处理的上下文

讨论和记录围绕具体需求展开，便于成员了解事情的来龙去脉。

- 在需求中评论，并提及项目成员。
- 记录阻塞事项，帮助团队识别推进障碍。
- 接收站内通知，查看与本人相关的协作变化。
- 通过统一时间线回顾状态流转、评估、交接和其他关键操作。

成员接手工作时，可以结合当前状态和历史记录了解背景。

### 6. 知识库与文书中心：让资料伴随项目持续积累

项目文档支持在线编辑、版本提交和历史查看。需求与文档可以双向关联，成员能从任务找到依据，也能从文档回到对应任务。

- 按项目组织、搜索文档与文件，保存独立项目资料。
- 查看文档历史，保留不同阶段的内容版本。
- 复制文档直达链接，便于有权限的成员定位材料。
- 在需求详情查看关联文档，在文档中查看关联需求编号、标题与状态。
- 学生版文书中心提供项目计划书、结题报告、答辩提纲和参赛材料说明四类结构草稿。

文书中心与知识库复用同一份项目文档，团队修改内容后可继续协作，无需维护两份独立材料。

### 7. 文件导入与附件管理：把已有材料接入协作流程

已有文字资料可以先导入、核对，再用于项目或需求描述；需要保留原件时，可以通过附件上传保存。

- 支持从 TXT、Markdown、DOCX 和文字型 PDF 提取正文，预览并编辑后填入项目或需求信息。
- 无需 AI 配置即可按正文填入说明；配置模型后可使用 AI 整理标题、背景、目标和验收标准等字段。
- 上传独立项目文件或需求附件，支持常用图片、PDF、文本、Office 文档及 ZIP 等类型。
- 按需求、方案、评估、开发交付、测试、验收及补充材料对附件分类。
- 支持附件下载、软删除和恢复，并在文件库查看已删除附件；操作受上传人及团队管理权限限制。

正文导入与原件保存是两个操作。扫描 PDF、复杂表格和公式材料需要额外整理或人工核对。

### 8. AI 质量评审：对照原文寻找材料缺口

需求详情提供 AI 评审入口，可以检查需求文档、研发方案或测试结果，并选择关联文档作为补充依据。

- 输出“文档检查通过”“需要修改”或“材料不足”等结论。
- 按检查项给出解释、修改建议和来源引用，便于回到原文核对。
- 保存评审时间、模型、资料版本和报告，支持 JSON 导出。
- 当关键资料变化后提示旧报告需要重新评审。
- 引用与发送资料不匹配、或输出结论互相矛盾时，拒绝保存该结果。

每次调用前确认发送资料与费用，复用个人 AI 服务配置；评审提供材料质量建议，人工评估与验收仍按原流程进行。

### 9. 项目分身与决策桌：为同一问题开展两条探索路线

当团队无法直接确定技术路线或实施方法时，可以建立一次项目分身探索，用共同目标和比较口径组织两条路线。

- 分别填写路线假设、最小试做计划、人时与费用预算、截止时间。
- 为试验指定负责人，记录完成情况、实际结果、投入及结论。
- 引用项目需求和文档，并保留创建时的资料快照。
- 接收超预算、逾期或决策条件缺失提示，明确下一步需要补齐的信息。
- 在决策桌并排比较两条路线，记录选择理由、放弃原因与重启条件。
- 跨路线选择需要保留的成果，生成成果文档与决策记录，并将路线冻结为只读历史。

例如，在两种实现方式之间选择时，团队可以先限定试做投入，再结合实际结果决定后续方向。这里保留的是成果内容和决策记录，不自动执行代码或合并 Git 分支。

### 10. 竞赛管理与 FirstStepAgent：把赛题转为启动材料

学生团队可以登记竞赛信息、维护队伍成员，并从竞赛进入材料准备与 AI 启动助手。

FirstStepAgent 结合团队输入的赛题、评分要求、技能、可用时间和资源约束，生成六类启动草稿：

| 启动材料 | 主要内容 |
| --- | --- |
| 竞赛分析与需求拆解 | 目标、交付物、范围、风险及缺失信息 |
| 开发执行提示词 | 背景、分阶段任务、输入输出与验收要求 |
| 技术栈与架构文档 | 推荐与备选方案、选型依据、模块及验证路线 |
| PPT 生成提示词 | 逐页结构、要点、证据、图示与演讲备注要求 |
| 里程碑与分工计划 | 阶段、角色、依赖、交付物与退出标准 |
| 验证与提交检查清单 | 复现、格式、引用、提交与答辩检查事项 |

无需 Key 即可预览并复制提示词；配置个人 AI 服务并确认后可以生成材料，人工核对后保存为六份项目文档。输出为草稿与提示词，不自动生成正式 PPT 文件或提交参赛材料。

### 11. ProofLoop 成果验证：从成果主张推进到补证行动

学生团队可以围绕“项目取得了什么效果”建立成果主张，将每个主张关联到评分要求、验证条件和文书原文。

- 绑定文书版本与连续原文引用，来源换版时提示证据过期。
- 选择多份文书检查前后表述是否一致，将疑点定位到具体引用。
- 将待补证事项转为项目需求草稿，指定交付角色后继续推进。
- 根据团队设定的重要度、预计工时和时间预算提供补证顺序建议。
- 记录署名人工核对、支持或不支持的判断及理由，保留核对历史。
- 导出同一快照下的 JSON 证据包和 Markdown 摘要，便于复查与交接。

团队可以持续进行“提出主张 → 检查材料 → 创建补证任务 → 完善材料 → 重新核对”的迭代。任务完成不会自动证明主张成立，证据包完整性校验也不等同于真实性认证。

### 12. 个人设置与 QQ 工作助手：延伸常用工作入口

个人设置集中管理 AI 服务配置，保存后可供竞赛启动、内容整理及质量检查等能力复用，支持配置验证、替换和删除。

在完成专用服务配置后，成员可以绑定本人 QQ，通过私信 `/工作` 查询当前待办，并按北京时间 09:00 和 18:00 接收汇总提醒。QQ 助手需单独安装与配置，未配置时不启用。

## 核心优势

### 1. 协作有流程，交付有依据

需求、方案、开发、测试与验收彼此衔接。团队既能看到任务进度，也能查明当前由谁处理、还缺什么材料、满足哪些条件才能进入下一阶段，减少反复确认和交接遗漏。

### 2. 项目分身，让方案选择建立在试做结果上

面对技术路线或实现方式的分歧，可以围绕同一目标建立两条探索路线，分别记录假设、试验、负责人、预算和实际结果。

通过决策桌比较投入与产出，记录选择理由、放弃原因及重启条件，并保留选中的成果，形成可回顾的决策过程。

### 3. 成果验证闭环，让结论能够追溯到证据

ProofLoop 将成果主张与文书原文、版本和验证条件关联起来，支持跨文书一致性检查、补证任务、署名人工核对以及证据包导出。

当来源文书或关键内容发生变化时，相关记录会提示过期，帮助团队持续检查“材料是否仍然支持当前结论”。

### 4. AI 融入具体工作环节

AI 能力覆盖竞赛启动、导入内容整理，以及需求、方案和测试材料的质量评审。评审建议附带来源引用，便于成员回到原文核对和修改。

AI 检查结果保留人工判断环节，不自动代替审批、测试或验收。

### 5. 文档与需求双向关联，知识随项目积累

需求可以关联项目文档，文档也能直接查看对应需求及状态。配合版本历史、文件库和统一时间线，团队能够将背景、方案、执行记录与成果集中保存，便于交接和复盘。

### 6. 多团队协作，角色与权限清晰

支持多团队加入与切换，并区分团队身份和项目角色。通过团队与项目权限校验、责任转交、归档只读和审计记录，为协作提供明确的管理边界。

### 7. 企业与学生两类场景，使用入口各有侧重

企业版聚焦研发交付，学生版聚焦竞赛与创新实践，两者共享项目协作基础能力，并提供各自的应用入口与界面主题，便于不同团队按实际任务开展工作。

## 适用场景

| 场景 | 主要价值 |
| --- | --- |
| 企业研发与产品迭代 | 串联需求、方案、开发、测试和验收 |
| 学生竞赛与创新项目 | 组织准备材料、团队分工和成果验证 |
| 课程设计与团队实践 | 明确责任，保留过程与交接资料 |
| 多方案探索与技术选型 | 控制试做投入，比较实际结果，保存决策依据 |

**产品主张：让需求有承接、过程可追踪、决策有依据、成果可验证。**
