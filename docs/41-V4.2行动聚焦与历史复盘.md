# V4.2 行动聚焦与历史复盘

产品4.2.0，前端3.17.0，后端2.24.0，2026-10-22（Asia/Shanghai）。4.1.0已经交付，本轮单独升MINOR。

## 本轮反思

1. 4.1已能执行行动，但列表只有分页，团队难以找到本人负责、逾期和需要独立确认的事项。
2. 截止日只能借用认领或重新分配调整，会重置状态/当前成果，日期维护与责任交接混在一起。
3. 检查点只展示最近5条并比较最近一条，难以回看早期基线，也没有可交接的完整对比简报。
4. 操作冲突虽保留输入，但弹窗持有旧版本，用户无法就地核对新版本再重试。通知接收人也应同时核对团队与项目成员资格。

## 三项新增能力

### 行动聚焦筛选

项目概览 → 行动与交付跟进。支持全部、我的、待我确认、逾期范围，以及状态和关键词组合；关键词匹配行动、验收要求、来源需求标题/CF编号及当前负责人姓名。搜索按普通文字匹配，百分号及正则符号不当作通配符。

服务端先组合筛选再分页，每页20项，返回匹配总数。上方数量统计全项目，明确不受当前筛选影响；“我的”包括本人所有状态，“待我确认”排除本人提交的成果与不可用来源；已完成行动不计逾期，逾期按北京时间日历日期计算。重置筛选同时清理范围、状态、搜索及页码。筛选仅保存在当前页面，不保存成团队共享视图。

### 独立调整截止日

行动负责人、创建者、产品负责人或团队管理员可填写原因，调整或清空未完成行动的截止日。改期不改变负责人、行动状态和已有成果；历史记录旧日期、新日期、原因、操作人与核对的需求版本。已完成行动须先重开，无日期变化的操作拒绝。沿用版本冲突与请求防重、归档只读、审计及通知同事务。

发生冲突时，弹窗保留日期与说明，可点击“核对最新行动，保留输入”读取当前版本后再人工核对。来源需求换版仍需主动确认；新状态不允许原操作时，服务端继续拒绝。本轮不新增后台定时提醒或外部发信。

### 历史检查点与推进简报

可分页读取全部已有检查点（每页20条），选择任意一条作为基线比较当前项目状态。历史选择不修改快照，新检查点仍以当前状态及真正最近一条记录校验；不能把旧基线当作最新记录覆盖历史。默认跟随最近检查点。

可导出Markdown推进简报，由服务端重新读取一致快照，记录北京时间、项目、所选基线ID与日期、真实状态差异、全项目行动及负责人/截止日/成果、下一步跟进建议。导出独立于行动筛选和页码，明确完整行动数量，避免把当前20条误当成全部。简报是记录对比，不是测试证明、需求验收或交付承诺；与所选基线相比暂无变化时明确显示。

## 权限、兼容与边界

所有列表、单行动核对、历史选择与简报导出均核对当前项目访问权限；不能引用其他项目的检查点。归档项目可读、可导出，不可改期。通知接收人同时核对团队及项目成员资格。

不新增数据库表或迁移，复用4.1的ProjectAction、ProjectCheckpoint及历史追加约束。全项目500项需求/500项行动、AI 200项未完成需求限制继续有效，超限拒绝，不静默截断。4.2须保留4.1迁移，不重写旧迁移、不补造历史。回退4.1时保留新写入的RESCHEDULE历史，旧界面无法识别该操作名称但数据不删除。

本轮没有重新验证真实DeepSeek输出质量，也没有增加自主执行。验证与部署状态见CHANGELOG.md及version.json；未部署不得视为线上能力。
