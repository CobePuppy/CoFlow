# CoFlow 3.1 项目空间

项目空间与个人/团队首页分开呈现，使用柔和深绿色侧栏（#315F49）、浅绿灰内容底色和白色工作面板。学生与企业端共享布局，首页、团队待办和通知保留原有团队范围。

## 页面和入口

导航提供项目概览、需求与交付、项目文档、GitHub仓库、项目分身、统计及模板，成员/设置位于侧栏下方。项目下拉框仅列出服务端授权返回的项目；团队切换清除旧项目与需求上下文，并进入新团队待办。无权访问时仍由API拒绝，不依赖隐藏按钮。

旧 view=tasks/documents/metrics/templates/forks、task 深链接继续有效。新增 view=project-overview 和 view=github；这两个视图同时纳入版本设置切换的上下文白名单。项目概览只使用现有项目指标，GitHub页面复用默认仓库设置，文件引用和PR仍在具体需求内维护。

## 需求工作台

四项真实指标收成一条可点击的指标栏，点击进入对应范围筛选；加载/错误不伪装为零。原有筛选、分页、列表/看板、常用视图和快捷操作保留。

桌面点击列表行打开右侧速览，点击需求标题或完整详情按钮进入原需求详情；看板仍直接打开完整详情。速览展示真实阶段、责任、截止日期、下一步说明、正文和最近开发交付摘要，不能在此绕过业务确认推进阶段。切换项目或视图会清除速览，查询使用现有任务缓存及失效规则；旧项目响应不能出现在新项目速览中。

宽度不足1200px时速览改用抽屉；650px及以下使用需求卡片，保留速览、完整详情、快捷操作和分页，避免桌面表格与手机卡片同时渲染造成重复交互目标。手机项目导航通过按钮打开，支持关闭、遮罩及Escape，品牌区域为关闭按钮留出空间。

## 代码边界

packages/web-core/src/features/project-space 包含 ProjectSidebar、ProjectHeader、ProjectMetrics/ProjectOverview、RequirementPreview、ProjectRepository 和局部样式。Workspace 继续承担URL状态、列表查询与现有模块装配；需求详情和业务动作仍由 requirements feature 提供。共享包不反向依赖任一应用。

本轮不新增后端接口、数据表或迁移，不搬动附件或数据库。不改变产品版本切换入口、GitHub个人授权隔离以及归档/只读限制。

验证结果和部署状态见根CHANGELOG的3.1.0条目。产品与前端3.1.0，后端2.12.0。
