# CoFlow 3.0 项目结构

产品 3.0.0，前端 3.0.0，后端 2.12.0。企业版和学生版使用独立入口、配置和构建，共享账号、权限、业务内核及同一数据库。两版是产品体验划分，不能作为数据权限边界；后端继续逐请求校验团队和项目成员权限。

## 目录与边界

| 目录                                        | 职责                                                     |
| ------------------------------------------- | -------------------------------------------------------- |
| apps/enterprise-web                         | 企业应用入口、企业导航和能力配置                         |
| apps/student-web                            | 学生应用入口、学生导航、竞赛、文书及 FirstStepAgent 页面 |
| apps/web                                    | 兼容开发宿主、公共资源及最终发布目录，不再存放业务页面   |
| apps/api/src/app.ts                         | 服务组装、路由注册及错误处理                             |
| apps/api/src/config                         | 仓库根路径、环境和运行配置                               |
| apps/api/src/modules                        | 按业务划分的路由、服务、校验和领域逻辑                   |
| apps/api/src/shared                         | 公共访问控制、数据库及路由上下文                         |
| apps/api/src/infrastructure                 | GitHub 客户端、加密、文件校验及静态站点服务              |
| packages/contracts/src                      | 前后端共享类型、状态、校验和纯业务规则                   |
| packages/web-core/src/app                   | 页面装配、版本注册、统一入口选择及主题                   |
| packages/web-core/src/features              | 需求、项目、团队、设置、GitHub、文档、通知等业务界面     |
| packages/web-core/src/shared                | API 客户端、公共界面、样式和通用工具                     |
| packages/ui                                 | 页面懒加载与错误边界等通用展示组件                       |
| tests/unit、integration、e2e                | 单元、隔离数据库集成及浏览器回归                         |
| scripts/dev、database、maintenance、release | 本地开发、数据库、维护和交付工具                         |
| prisma                                      | 当前模型及不可改写的历史迁移                             |

应用只能向共享包依赖；共享包不反向引用应用，企业应用不引用学生应用。学生特有页面由学生入口注册，企业构建不包含它们。contracts 通过自己的构建产物导出；API 打包时内联 contracts，以保持现有独立服务交付方式。架构单元测试检查反向依赖和静态循环依赖。

## 需求模块

Workspace 负责列表、筛选、分页和工作区装配；TaskDetail 负责详情；TaskActionDialog 负责业务动作；components 承载编辑、附件、资料及属性等组件；model 存放流程展示和筛选规则。GitHub 页面归入独立 feature，通过需求 ID 连接。

标准流程分为需求说明、方案与评审、开发交付、测试与验收、GitHub 仓库及动态记录；简易流程省略方案与评审。列表读取新增的 `GET /api/v1/projects/:id/task-summaries`，在数据库中筛选、计数和分页，仅返回摘要及处理人。完整历史和版本按详情读取。旧 `/tasks` 列表接口继续兼容。

## 后端模块

auth、workspaces、projects、requirements、overview、settings、documents、attachments、collaboration、notifications（由 collaboration 路由提供）、github、qq、ai、competitions、templates、proofloop、forks 各自维护业务。公共上下文保留已有事务锁、乐观锁、幂等、审计及权限规则；本次不改写历史迁移，不搬迁存储数据。

当前仍采用原有 Nest 宿主和 Express 路由，避免在结构迁移同时更换运行框架。部分遗留服务使用宽类型上下文，后续可逐模块收紧类型；大表的 JSON 查询可在真实数据监控后单独评估索引迁移。

## 版本选择

`/enterprise/` 与 `/student/` 是显式入口。未登录访问统一 `/` 先选择版本；已登录访问统一 `/` 使用服务端保存的默认偏好。既有带 app、task、invite、section 的根路径深链接保持有效。显式入口优先于默认偏好。

切换入口统一放在设置 → 使用偏好。“保存设置”保存默认版本；“切换到所选版本”进入该版本，并保留可共享的团队、项目和需求上下文，过滤不兼容的专属页面参数。编辑中的资料由未保存提醒保护；切换不复制账号或项目数据。
