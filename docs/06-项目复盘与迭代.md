# 项目复盘与迭代记录（2026-10-17）

## 判断

当前项目已经覆盖需求到验收的协作闭环，单元测试、隔离测试库和备份脚本提供了基础保障。下一阶段应优先改善异常路径、首屏加载与可维护性，再按实际数据量改造存储。继续增加入口和功能，会放大已有的维护成本。

本次为源码审查与前端可靠性迭代，不代表生产安全审计或容量评估。当前目录没有 Git 元数据，无法给出提交级差异和回滚记录。

## 本轮已完成

| 问题 | 修改 | 验证方式 |
| --- | --- | --- |
| 请求默认调用 response.json，网关 HTML 和空响应会掩盖真实状态 | 抽出 api-response.ts，错误保留 HTTP 状态，提供中文兜底提示，接受 204/205 无内容响应 | 新增 4 项单元测试，覆盖正常 JSON、HTML、空响应、401、409 和字段校验 |
| 非 JSON 的 401 会阻断原有登录态处理 | 在解析响应前执行原有会话失效处理 | 类型检查及响应解析回归测试；完整浏览器登录态回归待数据库恢复后运行 |
| 收藏缓存可能是对象、null 或含无效应用；写入失败会抛异常 | 校验数组与应用标识、去重，写入失败保留本次操作并提示 | 类型检查与格式检查；损坏缓存及存储禁用需补浏览器专项回归 |
| Markdown 静态加载增加入口依赖 | React.lazy 按需加载，局部 Suspense 显示加载状态 | 生产构建产生约 120.14 KB（gzip 37.11 KB）的独立块 |

本轮没有迁移数据库或升级依赖版本。没有测量首屏耗时，不能将拆包大小直接换算成加载速度提升。
